Purpose

This document defines the business-facing software requirements for the AI Second Brain system. It provides a clear delivery scope, approval-ready expectations, and a practical reference for implementation.




2

Project Overview

AI Second Brain is a private personal knowledge, context, and planning platform for a single primary user. It is designed to collect information from personal and official daily activity, preserve context, build a living knowledge graph, and support decisions and daily planning using the full available memory base.

The phase-one product is intended to act as a self-updating digital memory and decision-support assistant for the client.
3

Main Objectives

Build a personal knowledge graph from real daily context.
Combine files, conversations, contacts, meetings, recordings, and schedules into one memory system.
Support context-aware decision assistance and daily planning.
Reduce manual effort in storing and organizing information.
Enable exact search, related search, and timeline recall.
Preserve relationship history, priority, and discussion context around important people.

5

Information Capture and Collection

The system should collect information from approved phase-one sources and bring it into one unified knowledge base.

Approved Phase-One Sources
  • Local folders and files
  • PDFs and scanned documents
  • Notes and manual text entries
  • Bookmarks and saved links
  • Images and videos
  • WhatsApp message history, including group chats
Additional Context Sources
  • Voice call recordings
  • Voice notes
  • Meeting recordings
  • Calendar data
  • Contacts and address book data
  • Plaude device recordings and transcripts where available

Phase-one ingestion should support manual upload, folder sync, API integration where approved, export file import, mobile device sync, real-time ingestion where possible, and scheduled ingestion through cron or background jobs.

The system should keep original raw files and create searchable extracted content where applicable. Duplicate files should be ignored rather than stored repeatedly.

6

Knowledge Organization and Relationship Memory

The system should organize information into a master repository and build a personal knowledge graph around the user’s full context.

  • Identify useful relationships between people, conversations, documents, projects, tasks, plans, ideas, dates, meetings, calls, and recordings.
  • Support a self-updating knowledge graph that helps the user understand prior decisions, related work, and pending actions.
  • Present context-rich recall instead of isolated file retrieval.
7

Search, Recall, and Retrieval Experience

The user should be able to retrieve information using multiple search modes and advanced filters.

AI-assisted search
Direct exact search
Related-context search
Semantic search
People, project, date, and source filters
Answer, list, and timeline result styles
Voice search is not required in phase one. The priority is memory, context, planning support, and strong retrieval quality.
8

Contact and Relationship Intelligence

The system should maintain one combined person profile across available identity and interaction sources.

Combined Profile Context
  • Phone, email, name, and other identifiers where available
  • Chats and discussions
  • Shared files and media
  • Meetings, calls, and notes
Relationship Handling
  • Relationship history and interaction context
  • Priority or importance markers
  • Manual merge or split confirmation when AI matching is uncertain
9

Communication Memory

The platform should turn approved communication history into usable memory for recall, planning, and relationship context.

Communication SourcePhase-One Expectation
WhatsAppLive sync where feasible and approved, message history support, and group chat inclusion. Deleted messages should be ignored.
Calls and voice notesSupport call records, uploaded or connected recordings, and voice note ingestion.
Meetings and PlaudeSupport meeting recordings plus Plaude recordings and transcripts where available.

Built-in speech-to-text transcription is not a committed requirement for all voice sources in phase one. The system should support ingesting recordings now, while transcript-based processing may depend on imported transcripts or an approved processing flow.

10

Media and Document Storage

The system should support storage and recall of photos, videos, documents, voice notes, call recordings, meeting recordings, screenshots, research material, and raw imported source files.

  • Original source files should be retained, including raw backup material stored in object storage such as S3.
  • Items should be retrievable by file name, keyword, person, project, date, source, context, or related discussion.
11

Security and Access Control

The platform should remain private and controlled with a local-first operating model and active remote backup.

Phase-One Controls
  • Secure user authentication
  • Controlled integration setup using approved accounts and APIs
  • Restricted remote access to approved infrastructure
Backup and Sync Controls
  • Secure synchronization to an external private server
  • Active backup, restore, and synchronization support
  • Local encryption at rest planned later, not committed in phase one
12

Out of Scope

  • Multi-user collaboration workflows
  • Browser extension support
  • Browser history ingestion
  • Claude conversation ingestion
  • ChatGPT conversation ingestion
  • Gmail, Google Drive, OneDrive, Dropbox, Notion, Obsidian, Slack, and Telegram integrations
  • Mobile app delivery as a separate product
  • Guaranteed 100% perfect recall across all data sources
  • Fully autonomous correction of identity matching without user confirmation
13

Current Known Limitations

  • The overall product vision is broader than the committed phase-one delivery scope, so several future integrations remain intentionally excluded.
  • Live WhatsApp synchronization and direct communication-source ingestion depend on integration feasibility, platform access, permissions, and legal approval.
  • Built-in speech-to-text is not committed for all recordings in phase one, so some voice data may initially depend on imported transcripts or later processing enhancements.
  • Local encryption at rest is planned later and is not a committed phase-one requirement.
  • Retention behavior for completed project context still needs operational policy definition even though raw backup retention is expected.
14

Acceptance Criteria

  1. The system provides a private local-first environment for storing the user’s personal and official knowledge data.
  2. The system supports active backup, restore, and synchronization to a private external server.
  3. The user can ingest approved phase-one sources including local files, documents, notes, bookmarks, images, videos, WhatsApp history, call recordings, voice notes, meeting recordings, calendar data, contacts, and Plaude data where available.
  4. The system retains original raw source files and can create searchable extracted content where applicable.
  5. The system can identify and present useful relationships among people, files, conversations, projects, plans, and ideas.
  6. The user can retrieve information through AI-assisted search, direct search, related-context search, and advanced filtering.
  7. The system supports contextual recall using person, date, topic, project, source, and related metadata.
  8. The system maintains a structured and searchable history for important contacts, including combined profile context across approved data sources.
  9. The system supports manual confirmation for identity merge or split when AI matching is uncertain.
  10. Access is controlled through authentication and secure integration, backup, and remote access controls.
  11. Voice search interaction
15

Future Enhancements

  • Local encryption at rest
  • Broader cloud and productivity integrations
  • Richer timeline views
  • Deeper planning assistance and reminder workflows
  • More advanced relationship analytics
  • Wider autonomous semantic clustering and graph refinement
